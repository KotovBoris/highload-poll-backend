# Спека: Consumer (consumer)

> Источник истины по контрактам. Интеграционные тесты и реализация должны
> соответствовать этой спеке.

## Назначение

Consumer — слой асинхронной дедупликации и агрегации. Читает батчи голосов из
Kafka, дедуплицирует по fingerprint **in-memory**, считает голоса, дожидается
завершения опроса («done» от всех известных воркеров) и идемпотентно сбрасывает
итоги в сервис результатов. Только после подтверждения — коммитит offset.

## Модель обработки

```
сообщение батча → регистрация worker_id → дедуп по fingerprint → инкремент счётчиков
                → по завершении опроса: flush (идемпотентно) → commit offset → cleanup
```

Ключ `key = poll_id` гарантирует, что все сообщения одного опроса попадают в одну
партицию → обрабатываются одним consumer'ом → локальная дедупликация корректна.

## Состояние на каждый опрос (in-memory)

```go
type pollState struct {
    pollID      string
    dedup       map[string]struct{}   // fingerprint'ы, уже учтённые
    counts      map[int]int64         // option_id → голоса
    workersSeen map[string]struct{}   // воркеры, от которых были голоса
    workersDone map[string]struct{}   // воркеры, приславшие "done"
    endsAt      time.Time             // из сервиса результатов (кэш)
    firstSeen   time.Time
    lastSeen    time.Time             // последнее сообщение по этому опросу
    staleCount  int                   // подряд сообщений по ДРУГИМ опросам
}
```

Оценка памяти: ~250 MB на опрос при 5M fingerprint'ов (см.
[`05-layer-load.md`](../docs/architecture/05-layer-load.md)).

## Обработка сообщения

1. Десериализовать [`model.VoteBatch`](../internal/model/model.go:1).
   Битый JSON → лог + пропуск (сообщение не должно ронять consumer).
2. Получить/создать `pollState` по `poll_id`.
   - При первом появлении опроса: запросить `ends_at` через
     `ResultsClient.GetPoll`. Если недоступно — использовать `now + HARD_TIMEOUT`
     как безопасный дефолт, чтобы опрос не «висел» вечно.
3. `workersSeen[worker_id] = {}`.
4. Для каждого голоса: если `fingerprint ∉ dedup` → добавить в `dedup` и
   `counts[option_id]++`. Иначе — дубликат, пропустить.
5. Если `batch.Done` → `workersDone[worker_id] = {}`.
6. Обновить `lastSeen`; сбросить `staleCount` для этого опроса и увеличить
   `staleCount` у остальных активных опросов (они «остывают»).

## Логика завершения опроса

Опрос считается завершённым и готовым к flush, если **`now >= endsAt + CLOSE_GRACE`**
и выполнено **хотя бы одно**:

- **(a) кворум «done»:** `len(workersDone) >= ceil(COMMIT_DONE_PERCENT% × len(workersSeen))`
  (порог Y из архитектуры, по умолчанию 90%);
- **(b) остывание:** `staleCount >= COMMIT_STALE_MESSAGES` — подряд пришло X
  сообщений по другим опросам без новых по этому.

Дополнительно — **жёсткий таймаут**: если `now >= endsAt + CLOSE_HARD_TIMEOUT`,
flush выполняется принудительно даже без кворума (защита от зависшего воркера).

Проверка условий выполняется:
- после обработки каждого сообщения;
- периодически по тикеру (важно: опрос может «завершиться» без новых сообщений).

## Flush и коммит offset

Последовательность (см. [`05-layer-load.md`](../docs/architecture/05-layer-load.md)):

1. Собрать [`model.Results`](../internal/model/model.go:1): `total`, голоса по
   опциям, `workers_seen`, `workers_done`.
2. `ResultsClient.FlushResults(ctx, pollID, results)` — идемпотентно.
   - `written=true` — записано впервые;
   - `written=false` (409) — уже было завершено (replay) → тоже успех.
   - Ошибка сети/5xx → **retry** (offset не коммитим, состояние сохраняем).
3. Получив успех — **commit offset** по сообщениям этого опроса.
4. Удалить `pollState` из памяти.

## Коммит offset: контигуальный префикс по партиции

Ключевое требование: **нельзя коммитить offset, за которым есть необработанное
(не завершённое) сообщение** — иначе при падении потеряем данные.

Так как несколько `poll_id` могут попасть в одну партицию, ведём по каждой
партиции очередь «ожидающих» сообщений `(offset, pollID)`.

- Когда опрос завершён, его сообщения помечаются как «готовые к коммиту».
- Коммитим **непрерывный префикс** очереди партиции: пока голова очереди
  принадлежит завершённому опросу — снимаем и включаем в коммит.
- Коммитим максимальный offset префикса (одним вызовом `CommitMessages`).

Это гарантирует, что после рестарта consumer перечитает ровно незавершённые
опросы и не потеряет данные.

## Поведение при падении / рестарте

- Offset незавершённых опросов не закоммичен → consumer перечитывает их с
  последнего коммита.
- `dedup` пуст → пересчёт с нуля.
- Flush идемпотентен → двойного счёта нет.
- **Это штатный путь восстановления**, а не исключение.

## Ретраи и устойчивость

- `FetchMessage` — с backoff при ошибках чтения (не крутить цикл на 100% CPU).
- Flush — retry с backoff, ограничение по времени на попытку.
- Обработка одного сообщения не должна паниковать на мусоре — только лог и skip.

## Служебная ручка

### `GET /healthz`
`200 {"status":"ok"}` — процесс жив (без проверки Kafka — она может быть
недоступна временно, процесс считается живым).

## Требования к корректности и производительности

- **Ровно один flush на опрос** (идемпотентность защищает от повторов).
- **Дедупликация O(1)** — map; при 333K голосов/сек CPU ~7% ядра.
- **Память** — основной ресурс (~250 MB/опрос). Под нагрузкой число опросов на
  consumer ограничено числом партиций.
- **Никакой потери данных** при падении: offset коммитится только после
  успешного flush и только контигуальным префиксом.
- Тесты запускаются с `-race`.

## Зависимости и точки мокирования (для интеграционных тестов)

```go
type Reader interface { // internal/kafka.Reader
    FetchMessage(ctx context.Context) (kafka.Message, error)
    CommitMessages(ctx context.Context, msgs ...kafka.Message) error
    Close() error
}

type ResultsClient interface { // internal/resultsclient.Client
    GetPoll(ctx context.Context, id string) (model.Poll, error)
    FlushResults(ctx context.Context, id string, r model.Results) (bool, error)
}
```

Интеграционные тесты:
- **Фейковый Reader** — отдаёт заранее заданную последовательность сообщений
  (в т.ч. битые, дубликаты, несколько опросов, «done»), фиксирует коммиты.
- **Фейковый ResultsClient** — задаёт `ends_at`, фиксирует вызовы `FlushResults`,
  может эмулировать 409/ошибку/недоступность.
- **Управляемые часы** (`now func() time.Time`) — детерминированная проверка
  условий завершения без реального ожидания.
- Ключевые проверки: дедуп, счётчики, кворум (a), остывание (b), жёсткий
  таймаут, идемпотентный flush (409 → тоже commit), отсутствие коммита при
  ошибке flush, контигуальный коммит нескольких опросов в одной партиции.
