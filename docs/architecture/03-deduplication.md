# Дедупликация и fingerprint

## Требование из задания

> «дедупликация базовая (не слишком защищенную от обхода, достаточную на уровне
> обычных, не технически подкованных пользователей)»

## Стратегия fingerprint

```
fingerprint = hash(cookie)              если cookie есть
fingerprint = hash(IP + User-Agent)     если cookie нет (fallback)
```

### Cookie (primary)

- **Что:** серверный UUID-токен, выдаётся при загрузке страницы опроса (GET).
- **Как:** `Set-Cookie: voter_id=<UUID>; SameSite=Lax`.
- **Stateless:** сервер не хранит выданные cookie. Генерация UUID — O(1), без
  I/O. Коллизия UUID практически невозможна.
- **Почему primary:** уникальна для каждого устройства, не зависит от NAT
  (домашний, корпоративный, CGNAT — не важно, cookie своя у каждого).
- **Слабость:** очищается (инкогнито, ручная очистка, блокировщики). Тогда
  срабатывает fallback.

### IP + User-Agent (fallback)

- **Что:** хеш от внешнего IP-адреса + строки User-Agent.
- **Когда:** cookie отсутствует или не принята.
- **Почему fallback:** менее точен (NAT объединяет устройства), но для
  домашних зрителей (большинство) — достаточно. Один IP + один браузер =
  один fingerprint.
- **Слабость:** NAT (несколько устройств за одним IP → ложноположительная
  дедупликация). Для корпоративных сетей — проблема, но ТВ-зрители в основном
  дома, за личным роутером, с разными User-Agent.

## Когда выдавать cookie

При загрузке страницы опроса (GET `/polls/{id}`):
1. Клиент открывает страницу → сервер отдаёт HTML + `Set-Cookie`.
2. Браузер сохраняет cookie.
3. При голосовании (POST) cookie уже есть → используется как fingerprint.

## Дедупликация — асинхронная

См. [`02-product-assumptions.md`](02-product-assumptions.md), допущение 3.

- Hot path: принять голос → записать в буфер → ответить «OK». Без проверки
  дедупликации в моменте.
- Дедупликация: при flush батча — проверить fingerprint'ы против множества
  уже проголосовавших. Дубликаты отбросить, новые — учесть.

## Сценарии

| Сценарий | IP | Cookie | Fingerprint | Результат |
|---|---|---|---|---|
| 2 устройства дома | одинаковый | разные | разные | оба голосуют ✅ |
| 1000 устройств за NAT | одинаковый | разные | разные | все голосуют ✅ |
| 1 устройство, повтор | одинаковый | одинаковая | одинаковый | повтор отклонён ✅ |
| Очистил cookie, повтор | одинаковый | нет → fallback | одинаковый (IP+UA) | повтор отклонён ✅ |
| Инкогнито, повтор | одинаковый | нет → fallback | одинаковый (IP+UA) | повтор отклонён ✅ |
| VPN (разные IP) | разный | нет | разные | обход (допустимо) ⚠️ |
| 2 устройства, один браузер | одинаковый | нет → fallback | одинаковый (IP+UA) | 2-й отклонён (погрешность) ⚠️ |

## Осознанные допущения

- 2 устройства с одним браузером за одним NAT → 2-й голос отклонён (редкий
  случай, погрешность минимальна).
- Очистка cookie → можно проголосовать снова (обычные пользователи так не
  делают).
- VPN/прокси → обход (задача не требует защиты от этого).
- Cookie — «strictly necessary» (функциональный токен, не трекинг), не требует
  consent banner по GDPR / 152-ФЗ для анонимного опроса.
